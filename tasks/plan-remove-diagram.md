# Implementation Plan: Remove diagram command, embed diagrams in HTML & PDF

## Overview

Remove the `diagram` command and all supporting templates (graphviz, plantuml, mermaid CLI). Instead, make HTML and PDF reports **self-contained** — they embed mermaid.js and the DFD source, rendering the diagram inline as SVG with no external images needed.

**Net result:** ~220 lines removed, 3 fewer template files, no external tools required, all reports self-contained.

## Architecture Decisions

- **HTML report:** Embeds mermaid.js from CDN + DFD source → renders inline SVG on page load
- **PDF report:** Uses the same HTML template → chromedp navigates, mermaid.js renders SVG, then `PrintToPDF` captures it
- **Markdown report:** Already correct (DFD as embedded mermaid text)
- **No external images:** `diagram.png` references removed from all templates
- **No external tools:** No graphviz, plantuml, or mermaid-cli required

## Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| HTML reports require internet (mermaid.js CDN) | Low — mermaid.js is widely cached | Document requirement; PDF reports are self-contained since chromedp renders during generation |
| mermaid.js CDN is slow or unavailable | Low — use jsdelivr (fast CDN) | Document fallback: users can download mermaid.js and embed locally |
| mermaid.js version changes | Low — pin version in template | Use specific version (e.g., mermaid@11) |

## Open Questions (Resolved)

1. **Mermaid.js version:** Latest stable (e.g., mermaid@11)
2. **HTML rendering:** mermaid.js renders `<pre class="mermaid">` blocks to SVG on page load
3. **PDF rendering:** Same HTML template — chromedp navigates, mermaid.js renders SVG, then `PrintToPDF` captures it
4. **CDN dependency:** Acceptable for HTML (PDF is self-contained since rendered during generation)
