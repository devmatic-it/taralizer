# Token Cost Optimization Analysis

**Date:** 2024-01-XX
**Project:** taralizer
**Analysis:** Current state, waste identification, and actionable recommendations

---

## Executive Summary

The project contains **~513K total lines** across 140+ files. Approximately **30-40% of this is avoidable context** that inflates token costs without contributing to development reasoning.

**Key finding:** The single largest opportunity is the `.agents/skills/design-doc-mermaid/` directory (23.6K lines), which is an external skill package that gets loaded into context on every session.

**Estimated current waste:** ~150-200K lines (30-40% of total)
**Potential savings:** 50-70% reduction in per-session context size

---

## 1. High-Impact Opportunities (Immediate Action)

### 1.1 External Skill Package: `.agents/skills/design-doc-mermaid/`

**Size:** 23,594 lines (23.6K)
**Category:** External skill (not project code)
**Impact:** HIGH — loaded into context on every session

This skill contains:
- 17 example README files (500-1,200 lines each)
- Reference guides (800-1,000 lines each)
- Python scripts (300-600 lines)
- Templates (600-700 lines)

**Problem:** This is an **external skill** that gets loaded into every session's context. It's not project-specific code — it's a reusable skill that should be installed via the skills system, not committed to the repository.

**Recommendation:**
```
ACTION: Remove .agents/skills/design-doc-mermaid/ from the repository
WHY: It's an external skill, not project code. Install via skills system.
SAVINGS: ~23.6K lines per session
```

**Alternative (if needed inline):** Create a minimal `SKILL.md` that references the skill package without embedding examples/references.

### 1.2 Generated ANTLR Code

**Size:** 5,651 lines (`terraform_parser.go`) + 2,173 lines (`.antlr/terraformParser.java`) + interpreter files (~500 lines) = **~8,300 lines**
**Category:** Generated code (ANTLR grammar output)
**Impact:** MEDIUM — regenerated on every build

**Problem:** Generated code is committed to the repository but should be regenerated during build. Committing it inflates context without value.

**Recommendation:**
```
ACTION: Add .antlr/ and generated parser files to .gitignore
WHY: Regenerate during build from Terraform.g4
SAVINGS: ~8.3K lines per session
IMPLEMENTATION:
  1. .gitignore: .antlr/ pkg/terraform/.antlr/
  2. Makefile: antlr4 -o pkg/terraform pkg/terraform/Terraform.g4
  3. Document regeneration in CONTRIBUTING.md
```

**Note:** `terraform_parser.go` is large because it's generated. This is acceptable for ANTLR parsers — the generated file is the implementation.
